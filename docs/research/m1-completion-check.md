## ② 일 LLM 비용

### 방법

- `data/runs.json`(prod)·`data/runs-dev.json`(dev)을 `scripts/lib/cost.ts` `loadRuns`로 읽는다. 읽을 때 `RunsFileSchema`·`RunsDevFileSchema`(zod)로 검증하고, 파일과 env가 섞이면 실패한다.
- 하루 귀속과 합산은 비용 가드와 같은 규칙이다. 실행은 `startedAt`의 KST 날짜에 귀속되고(아침 수집 22:11Z는 다음 날 발행일), 금액은 `sumUsd`로 마이크로달러 정수 합산한다. 일 비용은 prod만 보고(D43), 월은 `monthToDate`·`assessDevUsage`로 prod+dev를 합산한다.
- 교차 확인은 두 가지다.
  - 기록 비용 재계산: prod 실행 20건마다 `costUsd`가 토큰 × `MODEL_PRICING`(claude-haiku-5-5, **단건** 단가 — 브리핑은 Messages API 단건, D28) 값과 같은지 본다.
  - 브리핑 ↔ 실행 기록: 게시된 브리핑 파일마다 그 `runId`가 runs.json에 있는지, LLM 줄이 있으면 비용이 0보다 큰지, `summarized` = LLM 줄 수이고 `downgraded` = 템플릿 줄 수인지 본다.

### 구조상 상한(참고)

하루 브리핑 요청은 상한 3건이다(`BRIEF_DAILY_REQUEST_CAP` — scripts/lib/brief-publish.ts, FR-29 재시도 포함). 요청 1건의 출력은 `max_tokens` 16,384(D57) × $0.50/MTok = $0.008192가 최대다. 지금까지 요청당 입력은 약 5천 ~ 8천 토큰이었는데, 넉넉히 1만 토큰($0.001)으로 잡아도 최악의 날은 3 × 약 $0.0092 ≈ **$0.028**로 예산의 30% 아래다. 실행 전 최악값 예상으로 예산을 넘으면 LLM 없이 템플릿으로 게시하는 가드(FR-27 — `estimateBriefWorstCase`·`decideBriefBudget`)도 있다.

### ④-b 화면 — out/ 정적 export HTML

**방법.** `npm run build`로 out/을 다시 만들었다(기존 out/은 10-25 빌드). 홈, `/news/`, 날짜 아카이브 14개 등 16페이지의 HTML을 happy-dom `DOMParser`로 파싱했다(스크립트는 실행하지 않음). 각 페이지가 싣는 호의 데이터(삭제 요청 제외 — `configs/takedowns.json`은 지금 비어 있음)와 아래를 대조했다.

- 카드 목록: `ol#feed > li > article`의 id 순서가 데이터 카드 순서와 같은지
- 카드마다 확인한 것
  - 제목 링크 `href`가 `src[0].u`와 같은지
  - 제목에 보이는 글자(↗ 장식·화면 밖 글자 제외)가 `t`와 같은지
  - 메타 줄 출처명이 `src[0].n`과 같은지
  - 출처가 2건 이상이면 펼침 목록의 행마다 href·출처명이 `src[]` 순서대로인지
  - 카드 안 외부 링크가 모두 그 카드 출처 링크인지

### ④-c 원제목·링크 ↔ 피드 원문 (2026-10-29 호)

**대상.** `data/news/2026-10-29.json` 45장이다(파일 생성 2026-10-28 22:11Z = 07:11 KST, 피드 받기는 약 1시간 뒤).

| 구분 | 대표 출처 | 카드 |
|---|---|---:|
| 해외 | BBC Sport | 15 |
| 해외 | Gianluca Di Marzio | 10 |
| 해외 | the Daily Briefing | 3 |
| 해외 | The Athletic | 2 |
| 국내 | 인터풋볼 | 13 |
| 국내 | 베스트일레븐 | 2 |

**받기 — 수집기와 같은 함수·설정.**

- 소스: `planDailySources(sources).feeds`. 수집 조건(enabled ∧ terms_checked)을 통과한 일일 RSS 루프 13개다(BBC 4 · The Athletic · the Daily Briefing · Di Marzio · Relevo · 인터풋볼 2 · 풋볼리스트 · 베스트일레븐 2).
  - 크롤링 소스: 등록된 크롤러가 없어(`CRAWLER_SOURCE_IDS` 비어 있음, M1-05 보류) 해당 소스가 없다.
  - 검색형 소스: Google News · GDELT는 비활성이다.
  - 그래서 "범위 밖"으로 뺀 카드는 0장이다.
- 요청: `scripts/lib/rss.ts` `fetchFeed`를 **소스당 정확히 1회** 불렀다(재시도 없음). 설정은 다음과 같다.
  - User-Agent: `feedUserAgent("sguys99@gmail.com")` = `EuroDigestBot/0.1 (+https://github.com/sguys99/euro-digest; sguys99@gmail.com)`. collect.yml의 `CONTACT_EMAIL`과 같다.
  - 상한: `DEFAULT_FEED_POLICY`의 타임아웃 15초 · 본문 5 MiB · 같은 호스트 리다이렉트 3회.
  - 순서: 소스를 하나씩 순서대로 받았고, 같은 호스트는 1초 이상 띄웠다.
- 결과: 13건 모두 HTTP 200 · 파싱 성공이다. Di Marzio는 같은 호스트 리다이렉트 1회를 그 요청 안에서 따라갔다(HTTP 왕복은 모두 14회).

**수집기가 원래 하는 처리 — 그대로만 적용.** `parseFeedXml`이 rss-parser(xml2js)로 XML 엔티티와 CDATA를 푼 다음, `normalize.ts` `normalizeFeedItem`과 같은 정리를 한다.

- 제목은 `cleanTitle`로만 정리한다.
  1. HTML 엔티티 디코딩: 이름 6종과 숫자 엔티티를 바뀌지 않을 때까지 최대 3회 푼다. 0x80 ~ 0x9F는 Windows-1252 대응표로 바꾸고, 글자로 들어온 C1도 같은 표로 바꾼다.
  2. 줄바꿈·탭이 든 공백 구간을 공백 1칸으로 바꾼다.
  3. 남은 제어 문자를 지운다.
  4. 앞뒤 공백을 지운다.
- 링크는 앞뒤 공백만 지운다.
- 카드는 `buildCard`가 `t = item.title`, `src[0].u = item.url`로 그대로 옮긴다.

비교는 이 처리 뒤의 문자열이 **완전히 같은지**(`===`)로 했다. 링크 대조도 같은 문자열인지로 했다.

| 범위 | 카드 | 대표 제목 일치(원문 그대로) | 불일치 | 확인 불가(피드에서 빠짐) | 범위 밖 | 나머지 출처 링크 피드에 있음 | 매체명 불일치 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 해외(lang ≠ ko) | 30 | 27 (26) | **0** | 3 | 0 | 3/3 | 0 |
| 국내(lang = ko) | 15 | 15 (15) | **0** | 0 | 0 | 0/0 | 0 |
| 전체 | 45 | 42 (41) | **0** | 3 | 0 | 3/3 | 0 |

- 불일치는 **0건**이다. 확인할 수 있었던 42장 중 41장은 정리 전 피드 원문 제목과도 같았다.
- 나머지 1장(`c_cc178a37c3`, BBC Sport — football · european 두 피드에 같은 항목)은 피드 제목 끝에 공백이 하나 붙어 있었다. `cleanTitle` ④(앞뒤 공백 정리)를 거친 뒤 일치했고, 보이는 글자는 같다(D45 '보이는 글자 불변').
- 확인 불가 3장(`c_88520ec10f`·`c_64a8f36206`·`c_6f8754afd9`)은 모두 Di Marzio 카드다. 그 피드는 항목을 10개만 싣는다. 이 3장은 그날 Di Marzio 카드 10장 중 원문 발행이 가장 이른 것(10-28 19:45 ~ 20:00Z)이고, 받았을 때는 피드에서 빠져 있었다. 나머지 7장은 일치했다.
- 같은 링크가 여러 피드에 있으면서 제목이 서로 다른 항목은 없었다.
- 다출처 카드의 나머지 출처 3건(BBC + The Athletic 카드 2장의 Athletic 출처 2건, BBC + BBC 카드 1장의 BBC 출처 1건)도 링크가 피드 항목과 같고 매체명도 같았다.
