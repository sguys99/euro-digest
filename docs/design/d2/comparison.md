## 2. 축 매트릭스 (시안 × 5축) — 모든 쌍이 4축 다르다

| 축 | A | B | C |
|---|---|---|---|
| 레이아웃 구조 | 1단 명단 행 · 표(1024+ 목차 + 11열) | 티켓 카드 격자(1024 2열 · 1280 3열) · 스텁 | 2단 지면(본문 + 옆단) · 세로 타임라인 · 색인 |

1. **기본 = A** — 셸 연결, 한국 선수 목록(375 보기 탭 · 1024+ 11열), 선수 상세의 시즌 기록 표 · 1280 옆단, 이적 목록 원장 행 + 왼쪽 필터 체크 목록, `/my`(다음 경기 경기 id 합침 · 최근 결과 · 관리 목차 열), 온보딩(5줄 아래 진입 줄 + 1·2·3 체크 목록), 홈 위젯(어젯밤 한국 선수 행 · 이적 핫 리스트 행 · 내 팀 소식 · A매치), 결과 가림 칸(`--hatch` + "보기" 44px).
2. **B에서** — 선수 상세 머리(큰 선수 티켓: 키트 스텁 + 시즌 출전 분 큰 숫자 + 팔로우 · 팀 화면 + 꼬리표 UCL · 이적설 · 대표팀), 다음 경기 '입장권'(킥오프 큰 숫자 + .ics — 선수 상세 · `/my` 공통), 팔로우 버튼 컴포넌트(미니 스텁 접힘 · 한도 이유 문장), 숫자 상태 규칙(실선 / 윤곽 / 대시).
3. **C에서** — 주간 리포트 화면 전체(MVP 머리기사 · MVP 점수 박스 · 총평 단 · 기록 박스 표 — B의 90분 막대를 분 열 옆에), 선수 상세 최근 5경기 로그 행(집계 전 칸 = 대시 + 점선 + 캡션 1줄), 이적 카드 펼침의 세로 타임라인(핫 리스트 → :target 도착), 검색 오버레이 · `/search/`의 색인 구조(뉴스 행은 A), 자리 조형 규칙(점선 + 도장 + reason + 채울 단계 · 빈 기준선 · 빈 밑줄).
4. **혼합 조정** — C 주간의 375 MVP 점수 박스를 한 줄 높이로 줄여 기록 표를 앞으로(현재 1,098px), 제품 화면의 FR ID · 작업 메모 제거(§5), A 윤곽 숫자를 `--ink-2` 윤곽으로(내부 하한).

이유
- 목록 · 이적 · 마이처럼 **비교하고 고르는 화면**은 A의 명단 행이 375 첫 화면 5명 · 1280 이적 2건으로 가장 빠르고, D1 순위표 · 라운드와 같은 문법이라 구현이 가장 가볍다(난이도 하).
- 선수 상세 머리는 B 티켓이 D1에서 확정한 팀 티켓과 짝을 이뤄 **'선수가 주인공'** 인상을 한 화면에 모은다. 큰 티켓을 머리 1곳에만 써서 B의 약점(길이 · 상자 격자 · 다크 키트 면)은 피한다.
- 주간 리포트 · 이적 타임라인 · 검색처럼 **시간 순 이야기와 색인**이 있는 곳은 C의 지면 문법이 가장 세련됐고, 지금 얇은 데이터(총평 자리 · 로그 2칸 · 이적 3건)를 '조판 대기'로 정직하게 보인다. scope §8의 예상 혼합(A + B 머리 + C 주간)에 C의 타임라인 · 색인 · 자리 규칙을 더한 안이다.

## 10. 사용자 확인 질문

**Q1 시안 선택**
1. A 스쿼드 명단
2. B 시즌권
3. C 주간 지면
4. **혼합: A 기반 + B 선수 티켓(상세 머리 · 입장권 · 팔로우 · 숫자 규칙) + C 주간 리포트 · 이적 타임라인 · 색인 검색 · 자리 규칙 — 추천(§9)**
5. 혼합 최소: A 기반 + B 선수 상세 머리 + C 주간 리포트만(scope §8 예상안 — 타임라인은 A 펼침 목록, 검색은 A 명단 행)

**Q2 스코어 표기 방향(scope §6 #6)** — 선수 상세에 출전 로그(소속팀 기준)와 다음 경기(홈-원정)가 함께 있다
1. **맥락별 — 선수 · 팀 기준 행(로그 · 목록 · 마이 결과 · 홈 칩 · 주간)은 W/D/L 칩 + 기준 팀 득점 먼저 + 홈/원정 글자, 블록 머리에 "결과는 {팀} 기준" 한 줄 / 경기 기준(다음 경기 · 오늘 밤 · 라운드 · 팀 일정)은 홈 팀 먼저(DESIGN §3.5 그대로) — 추천.** 세 시안이 모두 이렇게 했고, 칩이 늘 스코어 앞에 있어 두 순서가 섞여 보이지 않는다
2. 어디서나 홈-원정 순서, 선수 기준 행에는 W/D/L 칩만 더함(스코어만 보면 소속팀 득점이 앞인지 매번 확인해야 함)
3. 어디서나 기준 팀 먼저(라운드 · 팀 일정까지 — D1 확정 표기 변경)

**Q3 결과 가리기 적용 범위(scope §4 #6 · FR-37)** — 가림 칸 모양(`--hatch` + "보기" 44px)은 세 시안 공통
1. W/D/L · 스코어만 가림, 골 · 도움 · 출전 상태 · 분은 표시(A)
2. **W/D/L · 스코어 + 골 · 도움 가림, 출전 상태 · 분은 표시(B) — 추천.** "1골" · 골 시각이 경기 흐름을 짐작하게 한다. 출전 여부 · 분은 결과가 아니라서 한국 선수 팬이 가장 먼저 알고 싶은 정보를 남긴다. 홈 '어젯밤 한국 선수' 칩 · 선수 로그 · 주간 MVP 근거 줄에 같은 규칙
3. 출전 상태 · 분까지 모두 가림(가장 안전하지만 결과 가리기 켬 상태에서 한국 선수 화면이 대부분 빈칸)

**Q4 이적 타임라인 범위(scope §6 #4)** — 김민재: 단계 근거 카드 2건 + 단계 없는 이적 분류 카드 5건(아스널 · 토트넘 · AC 밀란)
1. 단계 근거(`history`)만, 나머지는 "관련 기사 n건" 링크(A)
2. **단계 근거 + 같은 선수의 이적 분류 카드를 '보조 · 단계 없음' 노드로 함께(C) — 추천.** 이적 창에 기사 대부분이 단계 필드 없이 오므로 근거만 보이면 7건 중 2건만 남는다. 노드 모양(펀치 vs 눈금)으로 근거와 보조가 구분된다. 단, 카드 머리는 '최근 행선지'(아스널)이고 보조 노드에는 다른 행선지 기사도 섞이므로, 행선지별 카드 분리 여부는 M4-01 데이터 결정으로 남긴다
3. 행선지별 카드로 나누고 각 카드에 그 행선지 기사만(`transfers.json` 선수 단위 → 이적 건 단위 — 스키마 변경, M4-01)

**질문 없이 추천대로 반영할 항목(세 시안이 같은 답을 냈거나 차이가 작음 — 다르게 원하면 알려 주세요)**
- 온보딩 진입 위치(scope §4 #13): 홈 '오늘의 5줄' 바로 아래 한 줄 → 펼침. 첫 방문 · 팔로우 0일 때만, 모달 없음 — 375 첫 화면 5줄 4줄(2026-10-23 결정)을 밀지 않는다(세 시안 공통).
- 팔로우 버튼 위치(scope §4 #3): 선수 상세 머리 · D1 팀 티켓 몸통 오른쪽 위 · `/my` 관리, 한도 5에 이르면 점선 비활성 + 이유 문장(세 시안 공통, 컴포넌트는 B).
- 팀 한줄평 · 주간 총평의 'AI 작성' 라벨(scope §4 #9): **단 머리에 한 번 + 생성 날짜**(B · C). 5줄은 줄마다 라벨이지만 문단 블록은 한 번이면 충분하다. 팀 한줄평 위치는 D1 팀 티켓 아래 · 팀시트 위(A · B 공통).
