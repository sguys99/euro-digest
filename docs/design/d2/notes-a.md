### A가 제안하는 결정(사용자 확인 필요 — scope §6 · §4)
- **스코어 표기(§6 #6)**: 선수·팔로우 팀 기준 행(로그·목록·마이 결과·홈 칩)은 W/D/L 칩 + 소속팀 득점 먼저, 경기 기준 행(다음 경기 · 오늘 밤)은 홈 팀 먼저 두 줄 대진. 칩이 늘 스코어 앞에 있어서 두 순서가 섞이지 않는다.
- **결과 가림(§4 #6)**: W/D/L 칩 + 스코어만 빗금 칸(--hatch, "보기" 44px)으로 가린다. 분·출전 상태·골은 결과가 아니라서 그대로 둔다. 골까지 가리는 안도 가능하다.
- **온보딩 진입(§4 #13)**: 홈 5줄 바로 아래 한 줄 진입 → 펼침이다. 모달이 아니라 375 첫 화면 5줄 4줄을 지킨다.
- **팔로우 버튼 위치(§4 #3)**: 선수 머리 오른쪽 위 · D1 팀 티켓 몸통 오른쪽 위 · 마이 관리(정사각 토글). 한도에 이르면 점선 비활성(aria-disabled)으로 두고, 누르면 토스트로 이유를 알린다.
- **팀 한줄평(§4 #9)**: D1 팀 티켓 바로 아래, 팀시트 위에 둔다. 한줄평 끝에 "AI 작성"(5줄과 같은 상자)을 붙이고, 강점 2 · 약점 2는 번호 행, 생성 날짜는 아래 줄에 둔다.
- **타임라인(§6 #4)**: 단계 근거 카드(history)만 넣고, 필드 없는 이적 분류 카드 5건은 각주로 둔다. 기사가 1건이면 펼침 버튼을 두지 않는다.

| 모션 | 찍힘 150ms(보기 탭 · 필터 결과 · 타임라인 행 · 온보딩 단계 · 검색 결과 · 가림 칸 드러남), 테마 잉크 전환 200ms. `prefers-reduced-motion: reduce`이면 전부 0이고, 스크립트도 찍힘 클래스를 건너뛴다. 첫 로드에는 진입 모션이 없다 |

## 6. 자체 검토에서 고친 것
1. **가로 넘침**: 375에서 검색 프레임이 467px로 넘쳤다 → `.grid2>*{min-width:0}`. 1280 마주 보는 면의 이적 행이 넓은 표 격자를 써서 넘쳤다 → 넓은 격자를 `/transfers` 목록(`.xr--w`)에만 쓴다. 1024에서 명단 표가 769px로 넘쳤다 → 1024~1279 열 폭을 따로 줄였다.
2. **1280 명단 표**: 375 전용 UCL 줄이 1280에도 보였다(`!important` 특이도 충돌 — 선택자 범위로 정리했다). '상대' 열이 글자 단위로 끊겼다(1. FC Magdeburg) → 열 폭을 다시 나누고 상대 이름은 단어 단위로만 줄을 바꾼다. 기록 연결 전 행의 이유 문구가 76px 칸에 세로로 끼어 있었다 → 3열을 합친 칸으로 옮겼다. 'UCL 참가 팀 아님'이 다섯 번 되풀이되었다 → "–" + 화면 밖 텍스트 + 범례로 바꿨다. 열 묶음 머리가 두 줄로 꺾였다 → 한 줄로 고정했다.
3. **375 밀도**: 처음에는 첫 화면에 4행이었다 → 쪽 머리 부제를 한 줄로 줄이고 행 위아래 여백을 8·7px로, 상대 줄을 한 줄 우선으로 바꿔 5행 + 일부로 늘렸다. 375에서 숨던 상세 옆단(다음 경기 · 이적설 · 대표팀)과 마이 관리 열을 지면 흐름으로 꺼냈다.
4. **이적 필터 위치**: 375에서 필터가 쪽 제목보다 위에 왔다 → 머리 · 필터 · 목록을 격자 형제로 나눠 375 = 머리 → 필터 → 목록, 1024+ = 왼쪽 열로 배치했다. 빈 상태가 `hidden`인데도 보였다 → `[hidden]` 규칙을 더했다. 버튼형 텍스트 링크에 기본 테두리가 남아 있었다 → 초기화했다.
5. **타임라인 중복**: 펼치면 최근 기사가 두 번 보였다 → 펼친 동안 대표 기사 줄을 숨기고, 기사가 1건인 행에는 펼침 버튼을 두지 않는다.
6. **다음 경기 줄**: 296px 옆단에서 대진이 '팀 –' 꼴로 꺾였다 → 홈/원정 두 줄 대진(D1 오늘 밤 카드 문법)으로 바꾸고 .ics는 텍스트 링크로 옮겼다. MVP 근거 줄이 375에서 글자 단위로 끊겼다 → 팀 줄과 경기 줄을 나눴다.
7. **axe**: 키트 배지 약어가 `.pd-m b` · `.aff b` 규칙에 덮여 잉크색(2.91)이 됐다 → 배지 글자색 특이도를 올렸다. 강점/약점 자리의 `<i aria-label>` → 화면 밖 텍스트로 바꿨다. 없는 주차(W42·W44) 색인 글자에 비활성색(3.88)을 쓰던 것 → ink-2로 바꿨다.
8. **지어낸 문구 제거**: '벤치에서 끝났다'(홈 칩), 온보딩 진입의 '30초', 창 모드 견본의 '5줄 바로 아래로'를 지우고 데이터·FR 문구로 바꿨다.
9. 검색 입력의 브라우저 기본 지우기(×) 아이콘을 없앴다. 다크 오버레이 배경을 잉크 40%(밝은 막)에서 뒤표지색 62%로 바꿨다.

## 8. 혼합할 때 가져갈 만한 것
1. **명단 표(목록)와 보기 탭** — 375는 같은 표의 열 묶음만 바꾸고 1024+는 11열이다. D1 순위표와 한 문법이라 목록 · 필터 · 비교 화면에 가장 강하다(scope §8 예상 혼합 'A 기반 목록'과 같다).
2. **출전 분 거터** — 0 · 45 · 75 · '–'를 Barlow로 세운 열과 상태 글자 조합이다. 홈 '어젯밤 한국 선수', 선수 상세 로그, 명단 목차(숫자 = 최근 출전 분)에 그대로 재사용할 수 있다.
3. **이적 원장 행 + 왼쪽 열 필터 체크 목록** — 단계·Tier·소속 칸(Q3 ①)·경로·갱신이 열로 정렬된다. 0건 축은 점선 비활성으로 남겨 'Tier 1 결과 0'을 숨기지 않는다.
4. **스코어 표기 규칙** — W/D/L 칩 + 기준 팀 득점 먼저(선수·팀 기준) / 홈 먼저 두 줄 대진(경기 기준). 어느 안을 고르든 §6 #6 해법으로 쓸 수 있다.
5. **결과 가림 칸** — W/D/L + 스코어만 빗금 칸으로 가리고 "보기" 44px 버튼을 두는 방식이다. D1 순위표·라운드에도 같은 칸을 쓸 수 있다(§4 #6).
6. **온보딩 번호 1·2·3 체크 목록 + 홈 진입 줄** — 5줄 등번호 문법이라 새 모티프가 없고, 375 첫 화면을 건드리지 않는다.
7. **마이 '다음 경기' 경기 id 합치기 + 걸린 팔로우 이름** — 팔로우가 겹쳐도(아틀레티코–바이에른 UCL) 한 줄이다.
