## 2. 화면별 해법 (지시서의 위험 2개에 대한 답)

- **얇은 데이터 = 빈 지면 위험** → 자리를 '교정쇄 빈 칸'으로 조형했다. 점선 1.5px `--ink-3` 테두리 + 작은 '자리' 도장 + reason + 채울 단계(fillStage)만 쓰고, 문단 자리(주간 총평 3~5문장 · 팀 한줄평 · 강점/약점)는 **빈 기준선(괘선 5줄, 마지막 줄 짧게)**으로 보여 '조판 대기'로 읽힌다. 'AI 작성' 라벨은 그 단 머리(최종 위치)에 둔다. 로그 4·5번 칸은 날짜 거터 대시 + 점선 띠 + 아래 캡션 한 줄로 줄였고, 이적 핫 리스트 4·5번은 번호만 남긴 빈 줄, 이름 미등록 이적(로호)은 **빈 이름 칸(점선 밑줄)** + 이유 한 줄.
- **필터·검색이 약함** → 지면 문법으로 풀었다. 이적 필터 = **색인**(신청서와 같은 체크 칸 + 리더 점선 + 건수, 묶음 안 OR · 묶음끼리 AND, 0건 항목은 점선 비활성). 1024 이상은 왼쪽 목차 열에 고정, 375는 `<details>`로 접힌 '색인' 한 줄. 검색 = **책 뒤 색인** — 입력 전에는 한국 선수 가나다 색인(ㄱ·ㅅ·ㅇ·ㅈ·ㅎ), 입력하면 선수·팀·뉴스 묶음(리더 점선 + 건수)으로 결과. combobox + listbox(↑↓·Enter·Esc, 포커스 가둠). 결과 없음은 D0 빈 상태 '0' 윤곽 숫자 + 글자.
- **375 옆단 밀림** → 단일 DOM 4영역 그리드(목차 · 머리 · 옆단 · 본문)로, 375는 `머리 → 옆단(앞) → 본문 → 옆단(뒤)` 순서로 접힌다. 옆단을 앞·뒤로 나눠 핵심 박스(시즌 기록 · MVP 점수 · 이번 주 리포트)만 제목 바로 아래에 오고, 범례·다음 순위·팔로우 관리·결과 없음 견본은 본문 뒤로 간다.
- **scope §6 제안**: #6 스코어 표기 = 선수·팀 로그는 "W 6-1 · 홈" 꼴(소속팀 기준 득-실 + 홈/원정 글자), 머리에 "결과는 {팀} 기준(득-실)" 한 줄 / #4 이적 타임라인 = 단계 근거 2건(펀치 구멍 노드) + 같은 선수의 이적 분류 카드 5건(가로 눈금 노드, '보조 · 단계 없음')을 한 줄기에 — M4-01 판단용으로 둘 다 보여 줌 / #13 온보딩 진입 = 홈 '오늘의 5줄' 바로 아래(내 팀 소식 자리)에 '간지' 1장(375 5줄 첫 화면 보존) / Q3 ① 이적 카드 = "소속 바이에른 뮌헨"(보조 지면 칸) · "출발 미확인 → 행선지 아스널" 분리.

## 5. 자체 검토에서 고친 것

1. 이적 행선지 배지 약어가 "AR / S"로 깨짐 — `.sty__to b` 선택자가 배지 안 `<b>`까지 잡아 22px로 키움 → 자식 선택자로 한정
2. 타임라인·로그 날짜 거터에서 시각이 날짜와 멀리 떨어짐(그리드 행 늘어남) → `align-content: start`
3. 목록 줄 "UCL UCL 참가 팀 아님" 중복 → 라벨이 UCL로 시작하면 접두어 생략
4. 로그 4·5번 자리 칸이 같은 이유 문장을 두 번 반복 → 대시 + 점선 띠 + 아래 캡션 한 줄로
5. 벤치 행에 "0분"이 붙어 '벤치 · 미출전'과 중복 → 출전했을 때만 분, 명단 제외는 "–"(scope 규칙)
6. 1280 선수 상세의 옆단 아래가 길게 빔 → '이적설' 상자를 본문에서 옆단으로 옮김
7. `/my` 팀 '다음 경기' 줄이 2열 그리드에서 글자 단위로 쪼개짐 → 값을 한 칸으로 묶음
8. 이름 미등록 이적(로호)이 머리와 타임라인에 같은 원제목을 두 번 → 빈 이름 칸 + 이유 한 줄
9. 상대 시간이 날짜와 같은 문자열로 중복("10.11 (일) 00:00 · 10월 11일 (일)") → '…전'일 때만 표시
10. 1280 신청서에 세 칸이 한 장에 다 보이는데 단계 표시 "1 리그"가 현재 단계처럼 남음 → 1024 이상 단계 표시 숨김 + '신청 마치기' 버튼
11. 375에서 옆단(범례 · 다음 순위 · 팔로우 관리 · 결과 없음)이 본문 앞을 길게 막음 → 옆단을 앞·뒤로 나눠 375에서 뒤 블록은 본문 뒤로(`display: contents` + 영역 이름)
12. 375 견본 단계×Tier 표 가로 넘침(380px) → 375에서 단계 글자 숨김(행 머리가 같은 정보) · 구멍 13px
13. 375 신청서 팀 2열에서 "아우크스부/르크"처럼 단어가 잘림 → 560px 미만 1열
14. 44px 미달 16곳(선수 이름 링크 41px · 주간 표 이름 링크 25px) → 패딩·`min-height/min-width 44px`
15. axe: 단계 바 `<ol role="img">` 안 `<li>`(listitem 76건) → span으로 / 오버레이 listbox 안 section·ul·링크(필수 자식 위반) → listbox에는 group + option만, 입력 전 색인·'전체 결과' 링크는 listbox 밖으로
16. 비활성이 아닌 안내 글자의 `--ink-disabled`(3.88:1, axe) → `--ink-2`
17. 검색 입력의 브라우저 기본 지우기 ×가 닫기 ×와 겹침 → 기본 버튼 숨김 · 배경막을 지면 88%로(잉크 반투명은 다크에서 탁함)
18. 홈 375 '이적 핫 리스트' 섹션 위 여백 0(첫 자식 규칙이 지면 안 래퍼에 걸림) → 규칙 범위 축소

## 6. 장단점 · 난이도 · 번들/폰트

- **장점** — 'Editorial, not portal'이 가장 또렷함(큰 제목 하나 + 기록 박스) · 주간 리포트와 이적 타임라인처럼 시간 순 이야기에 맞음 · LLM 문단(총평 · 팀 단평)이 들어올 단이 처음부터 지면 안에 있음 · 필터 · 신청서 · 팔로우가 같은 체크 칸 문법
- **단점** — 목록이 길다(375 한국 선수 목록 약 3,770px, 첫 화면 1~2명) · 지금은 자리 상자가 여럿 보여 '예고면'처럼 느껴질 수 있음 · 1280에서 옆단이 본문보다 짧으면 아래가 빔 · 검색 결과가 많을 때(이강인 71건) 한 화면에 덜 들어감
- **난이도 중~상** — 4영역 지면 그리드(375 접힘 순서 · 옆단 앞/뒤 분할) · 세로 타임라인 · 색인 필터 섬 · 신청서 단계 섬 · 검색 오버레이 섬(combobox) · 결과 가림 칸. 정적 서버 컴포넌트 비중이 높다
- **번들/폰트** — 폰트 변화 0(EuroDigest Sans 400 181,376B · 800 190,580B + Barlow Condensed 600 27,892B · 800 28,048B = 417.8KB, 2패밀리, 새 파일 0). 새 색 토큰 0. 시안 인라인 JS 11.0KB / gzip 4.4KB(테마 · 토스트 포함) → 새 섬 추정 gzip 약 3KB → 초기 JS 약 147KB / 160KB. Pagefind는 첫 입력 때 지연 로드

## 7. 혼합 시 가져갈 만한 것

1. **주간 리포트 화면 전체** — MVP 머리기사(이름 112px) + 옆단 'MVP 점수' 박스(4점 96px · 산식 줄) + 총평 단(빈 기준선 자리 · 단 머리 'AI 작성') + 잉크 반전 머리의 기록 박스 표. scope §8의 예상 혼합(C = 주간 리포트)과 같은 결론
2. **이적 세로 타임라인** — 날짜 거터 + 2px 잉크 줄기 + 단계 근거(펀치 구멍 노드) / 보조 카드(가로 눈금 노드) 구분. A의 이적 행에서 펼침 상세로 넣어도 된다. 홈 핫 리스트 → 타임라인 항목 도착(:target)이 DR-08 '의미 있는 전환' 하나를 새 모션 없이 채운다
3. **자리 조형 규칙** — 점선 테두리 + '자리' 도장 + reason + fillStage, 문단 자리는 빈 기준선, 이름 자리는 빈 밑줄. 어느 안에 붙여도 같은 문법
4. **색인 = 필터** — 체크 칸 + 리더 점선 + 건수(D0 목차 행 확장), 0건 항목 점선 비활성. 같은 체크 칸을 팔로우 버튼 · 온보딩에 재사용해 입력 UI가 한 문법
5. **검색 오버레이 입력 전 상태** — 한국 선수 가나다 색인(첫 화면이 비지 않는다)
6. **375 옆단 앞/뒤 분할** — 단일 DOM에서 핵심 박스만 제목 아래, 나머지는 본문 뒤로
