### 3. 선택 이유

- **모바일 3초 스캔**: 375 첫 화면에 5줄 중 4줄이 보인다(A 3줄 · B 2줄). 카드 평균 높이는 181px(375)·149px(1280)로 셋 중 가장 짧고, 번호 → 도장 → 제목 → 출처 위치가 고정이다.
- **D1~D3 확장성**: 등번호·팀시트·리그표 은유가 D1(순위표·포메이션), D2(선수·이적), D3(티켓 OG·스텁 아이콘)까지 새 언어 없이 이어진다.
- **데이터 변동 내성**: 카드 높이 편차가 가장 작다(1280에서 129~183px). 5줄이 적은 날(S3·S4)도 번호 거터로 버틴다.
- **A로 보완한 이유**: C의 1280은 균일한 목록이라 포털 인상에 가깝다. 또 M1(우측 열이 빈 상태)에서 5줄 위치가 애매한데, C 원안 '5줄 우측 sticky'는 PRD D2 "홈 최상단 = 5줄"과 충돌할 수 있다. A의 머리기사 1장과 중앙 확장으로 두 문제를 모두 메운다. A의 연결 줄은 게재 번호에 교차 참조라는 쓰임새를 줘서, 번호를 순위로 오해할 여지도 줄인다.
- **B에서 하나만 가져온 이유**: 대회 필터 색 면 하나만 더해 1280의 단조로움을 깬다. 새 모티프는 늘리지 않는다.

| 기각한 안 | 이유 |
|---|---|
| A 단일 (40점, 차점) | 375에서 단 조판이 사라져 1단 목록이 되고, 5줄은 3줄만 보이며 카드 평균이 207px다. 아침의 에너지가 약하고, 한글 명조는 작은 UI 글자에서 덜 또렷하다 |
| B 단일 (35점) | 375 첫 화면을 표지가 차지해 5줄 중 2줄만 보인다. 극굵은 제목과 블록 키커 때문에 23장 피드가 피곤하고, 거대 '5'가 데이터 적은 날과 부딪친다. 구현 난이도도 가장 높다 |
| C 단일 (42점) | 1280 균일 목록(포털 인상)과 M1 1280의 5줄 위치 문제가 남는다. 사용자가 혼합(Q1 ①)을 골랐다 |

### 2. 선택 이유 (`comparison.md` §5 Q1 추천 그대로)

1. "제 N호" 티켓이 곧 호를 넘기는 장치라 D0 콘셉트(매일 한 호를 펴는 프로그램)와 가장 잘 맞고, 새 영역·새 모티프가 없다(스텁 = 절취선·노치·점선 칸).

3. 지면(5줄·피드)과 목차 열을 건드리지 않는다. B는 1024 이상 필터 목차를 첫 화면 바닥으로 밀고, C는 지면 머리를 가장 많이 늘린다. 비용은 티켓 +70px(375)·+76px(≥1024)와 섬 JS 약 1KB.

### 3. 선택 이유

- **순위표는 A**: 375에서 가로 스크롤 없이 첫 화면에 5행이 보인다(B는 4행, C는 순위표가 원장 아래 약 1,390px에 있다). 1024 이상은 펼침 없이 FR-42 열을 모두 보인다. 새 모티프 없이 D0의 번호 거터(큰 순위 숫자)와 티켓 스텁(팀 티켓)만 넓혀서 홈·뉴스와 한 권의 프로그램으로 이어진다.
- **팀 화면 포메이션만 B**: A의 사이드 피치는 작고, 교체 명단의 한국 선수(김민재)처럼 이 서비스 독자에게 중요한 사실이 B 팀시트에서만 보인다. 375에서 피치가 나오는 위치는 A 1,022px에서 혼합안 594px로 올라왔다(팀 화면 시작 기준).
- **헤더는 A 티켓**: 티켓 스텁이 곧 배지를 키운 것이라 팀 표식이 하나로 통일된다.

| 기각한 안 | 이유 |
|---|---|
| A 단일 | 375 팀 화면에서 피치가 1,022px 아래에 있다. 사이드 피치가 작고 교체 명단(한국 선수)이 없다 |
| B 단일 | 375 순위표가 가장 길다(약 1,410px). 승·무·패 개별 숫자가 없고, 1280 두 단이 11위에서 순서를 끊는다. 순위 화면까지 라인업 데이터 품질에 기댄다 |
| C 단일 · C 변동 리본(선택지 ⑤) | 셋 중 가장 촘촘해서 'Editorial, not portal'·3초 스캔 기준에서 가장 불리하다. 375 가로 스크롤 단서를 관리해야 하고 순위표가 원장 아래로 밀린다. 리본만 더하는 ⑤는 사용자가 고르지 않았다 |
