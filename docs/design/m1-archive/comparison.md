> 버전 **v0.1** · 작성일 2026-10-22 · 범위: `/news/[date]/`의 **이전·다음 호 이동 + 달력 점프**만(PRD FR-33). 지면의 다른 요소는 확정된 D0 혼합안(`docs/design/d0/concept-mix.html`, M1 공개 상태)을 그대로 재현했다.
> 근거: CLAUDE §1-1·§4, PRD FR-33·FR-34·§4 IA·§8.4, DESIGN §1·§2.10·§9.3·§10, DECISIONS D0 §4·§5 #1·#21·#32·#36. **결정은 사용자**이고 구현하지 않았다.

## 5. 사용자에게 묻는 것

**Q1. 날짜 이동 시안**
- **A 스텁 넘김 (추천)**. 이유 셋:
  1. "제 N호" 티켓이 곧 호를 넘기는 장치라 D0 콘셉트(매일 한 호를 펴는 프로그램)와 가장 잘 맞고, 새 영역이 없다.
  2. FR-33 '달력 점프'를 요일 정렬 월 달력으로 그대로 충족하고, 결호·창간 전·발행 전이 한 장에서 구분된다.
  3. 지면(5줄·피드)과 목차 열을 건드리지 않는다. B는 필터 목차를 첫 화면 밖으로 밀고, C는 지면 머리를 가장 많이 늘린다.

  비용은 티켓 +70px와 섬 JS 약 2KB(예산 안)다.
- B 지난 호 목차: JS 0이 가장 중요할 때.
- C 호 띠: 가까운 호를 자주 오가는 쓰임이 주일 때.
- 혼합 **A + 피드 끝 한 줄(B의 '‹ 제 7호 ······ 제 10호 ›')**: 45장을 다 읽은 뒤 위로 돌아가지 않고 바로 넘길 수 있다. 지금 `/news/`에 들어간 임시 텍스트 링크 자리를 이 모양으로 채우는 셈이다.

**Q2. 아카이브에 그날 5줄 싣기**
- **싣는다, 제목 '이날의 5줄' (추천)**.
  - 근거: PRD §8.4가 `data/briefs/`를 무기한 보존하는 이유를 "날짜 아카이브에서 그날 브리핑 표시"라고 적었다(D45 ③). 호는 5줄 + 뉴스이므로 지난 호도 발행된 그대로 보여야 한다.
  - 제목: 날짜를 단정하지 않게 '오늘의'를 '이날의'로 바꾼다(#36 '이 호에는'과 같은 원칙). 부제 "10월 19일(현지) 경기 기준"은 그대로 둔다.
  - 브리핑 파일이 없는 호(10-12~14)에는 블록을 싣지 않는다(#32).
- 싣는다, '오늘의 5줄' 그대로(기능 이름으로 유지).
- 싣지 않는다(`/news/`처럼 피드만).

**Q3. (A를 고르면) 꼬리표를 어디까지**
- **`/news/`(최신 호)와 날짜 아카이브에만 (추천)**: 홈 첫 화면의 5줄을 지킨다. 홈에서는 상단 내비 '뉴스'로 들어간다.
- 홈 티켓에도 단다: 어느 페이지든 티켓 모양이 같아지지만, 홈 375 첫 화면에 다 보이는 5줄이 4줄에서 3줄로 준다.

## 6. 남은 판단 (오케스트레이터)

- **상단 내비·뒤표지 '마지막 업데이트'**: 시안은 지금 구현대로 보는 호 기준(09:42)을 실었다. 10-22에 10-20 호를 보면 사이트의 실제 마지막 업데이트(10-22 09:14)와 다르다. 사이트 기준 + 날짜 표기로 바꿀지 정해야 한다(M1-30 이월 메모의 결정 사항).
- **아카이브 h1**: 시안은 화면 밖 h1 "제 9호 · 2026년 10월 20일 (화) 지면" → 5줄 h2 → 뉴스 h2 → 카드 h3로 두었다(`/news/`는 h1 "뉴스").
- **지난 호 카드의 상대 시간**: 이 호는 "2일 전"이지만, 7일이 넘은 호는 날짜 표기로 바뀌어 절대 시각과 겹친다(M1-31 이월 메모). 아카이브에서 상대 시간을 뺄지 정해야 한다.
- **A의 월 이동**: 지금은 10월 한 달뿐이라 월 버튼이 둘 다 비활성이다. 지난 달 격자를 미리 그리면 HTML이 달마다 늘어나므로, '그 달 첫 호로 가는 링크'로 두는 안을 추천한다.
- **캡처 환경 메모**: 07번 카드 원제목의 한자 '韓'이 스크린샷에서 빈 상자로 보인다. 서브셋(KS X 1001 한글) 밖 글자가 이 환경의 시스템 폴백에도 없어서다. 실데이터 그대로라 고치지 않았다(실기기에서는 시스템 한자 글꼴로 그려진다).
