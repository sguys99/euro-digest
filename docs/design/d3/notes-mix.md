### 가져오기 방식(새로 그리지 않음)
- `concept-a.mjs`: `sIcons` · `sOg` · `css`에 `export`만 붙였다.
- `concept-b.mjs`: `/offline/` 블록을 `offlineB({ h, h2 })`로, 30일 달력 표와 소스 표 행을 `cal30B()` · `srcRowsB()`로 함수만 빼냈다.
- `concept-c.mjs`: 검색 0 블록을 `searchZeroC()`로 빼냈다.
- 혼합안 CSS는 세 시안의 `css`에서 선택자 앞부분으로 규칙을 골라 온다(`pick()` — `@media` 안까지). 그 뒤에 이음새 규칙만 덧붙였다.
- **A · B · C 시안 HTML은 바이트 단위로 그대로다** — 리팩터 전후 `concept-{a,b,c}.html` md5 동일 확인.

## 3. 휴식기 판정 규칙(제안 — 구현 M5 또는 별도 작업, 사용자 확인 후)

입력: 발행일(KST, 빌드 시각의 KST 날짜) · 그날 브리핑 파일 · `configs/competitions.json` · `configs/national-team.json`.

1. **홈 오늘의 5줄에서만**(`variant="today"`). 날짜 아카이브 “이날의 5줄”은 S4 그대로 — 지난 호를 지금 설정으로 다시 쓰지 않는다(비시즌 변형과 같은 원칙, DESIGN §11.12).
2. 브리핑 mode `empty` + `emptyReason` `no-matches`(키 없는 옛 empty 포함) = “6개 대회 전날 끝난 경기 0”. 결과 지연(`results-pending`)은 늘 오류 상자(D60) — 휴식기 변형 아님.
3. 우선순위: **비시즌 → A매치 휴식기 → S4**. 모든 대회가 시즌 밖이면(`offSeasonFeature`) 비시즌 변형. 아니면 `restPeriodOf(발행일, { competitions, nationalTeam }).reasons`에 `international-window`가 있으면 A매치 휴식기 변형. 둘 다 아니면 S4.
4. 실을 경기 = `nationalWindowOn(발행일)`이 돌려준 기간의 `matchIds`(경기일 ±3일, 이어지는 기간 합침, `postponed` 제외 — `src/lib/national-team.ts` 그대로). 킥오프 순.
5. 경기 표기: 경기일(KST) `MM.DD` N2 실선 + `(요일) HH:MM KST` + 상대 + 홈/원정 · 대회명. `kickoffTbd`면 시각 대신 “시각 미정”. 이미 킥오프가 지난 경기는 날짜 `--ink-2` 400 + “끝남” 글자(숫자 상태 규칙상 값은 있으므로 실선 유지, 결과 · 스코어는 싣지 않음 — A매치 섹션이 가림 규칙과 함께 맡는다).
6. 문구는 기존 S4 문장 그대로 + 도장 “A매치 기간” + 기간 `MM.DD – MM.DD`. “리그가 쉰다” 같은 원인 서술은 쓰지 않는다(데이터에 없음, CLAUDE §1-7). `national-team.json`이 없거나 판정이 비면 S4.
7. 홈 A매치 섹션(M3-13)은 같은 판정으로 이미 5줄 바로 아래에 나온다 — 변형의 “A매치 섹션으로 ↓”는 그 섹션 `id`로 가는 같은 쪽 앵커.
